Lesson 04 · Pavona from the ground up

One Input, Multiple Representations

A good template reuses a user's answer — but transforms it only where the target format requires it.

Today's win

You'll scaffold the built-in Go library with a hyphenated project name, see why its module path keeps the hyphens while its Go package name changes them to underscores, then use the same pattern in a tiny custom template.

The design problem

One project name can have different jobs:

  • Module path: a repository-style path can contain hyphens — e.g. github.com/go-csvstream.
  • Go package clause: needs an identifier-style name — e.g. go_csvstream.
  • Human-facing text: should usually preserve what the user typed — e.g. go-csvstream.

Don't ask for three values when one source value plus a targeted transformation is enough. The built-in lib template is a working example:

go.mod.tmpl:  module github.com/{{.project_name}}
lib.go.tmpl:  package {{.project_name | sanitize}}
              return "Hello from {{.project_name}}"

The built-in Pavona helper sanitize lowercases letters, changes hyphens and underscores to underscores, and removes other non-letter/digit characters. It is useful for a conventional slug like go-csvstream; it is not a universal validator (for example, it doesn't ensure the result starts with a letter).

See it in a built-in

  1. Generate a library. Use a fresh output name: 
    pavona new lib go-csvstream-built-in -q
  2. Inspect the two representations: 
    grep '^module ' go-csvstream-built-in/go.mod
grep '^package ' go-csvstream-built-in/lib.go
grep 'Hello from' go-csvstream-built-in/lib.go
    Expect the module path and greeting to preserve hyphens; the package clause uses underscores. The source is in templates/lib/go.mod.tmpl and templates/lib/lib.go.tmpl.

Carry the pattern into your template

Create a tiny custom library template. These three files are enough to demonstrate the seam: raw value for the module, transformed value for the package.

  1. Define one input: 
    mkdir -p my-lib-template
cat > my-lib-template/config.cue <<'EOF'
package template

name:        "my-lib-template"
description: "A minimal custom Go library"

variables: {
	// Go module suffix (use a slug, e.g. go-csvstream)
	project_name: string
}
EOF
  2. Render that input in two forms: 
    cat > my-lib-template/go.mod.tmpl <<'EOF'
module github.com/{{.project_name}}
EOF
cat > my-lib-template/lib.go.tmpl <<'EOF'
package {{.project_name | sanitize}}

// ModuleName returns the module suffix.
func ModuleName() string {
	return {{printf "%q" .project_name}}
}
EOF
    printf "%q" is Go's text/template built-in; here it safely quotes the value as a Go string literal.
  3. Generate and inspect: 
    pavona new ./my-lib-template go-csvstream-custom -q
grep '^module ' go-csvstream-custom/go.mod
grep '^package ' go-csvstream-custom/lib.go
    Expect github.com/go-csvstream-custom in go.mod and package go_csvstream_custom in lib.go.

Keep transforms in rendered file contents. sanitize is registered for *.tmpl file content. Pavona also renders directory and file names, but its path renderer does not register sanitize; using it there fails with an undefined function error. If a value becomes a path, design that input to already be path-safe.

A reusable design rule

Output needs…Template it as…
The user's exact project slug{{.project_name}}
A Go package-style form{{.project_name | sanitize}} in a rendered file
Stable boilerplate, unchanged everywhereA verbatim file — no .tmpl
A choice that actually varies between projectsA separate config.cue variable, with a default if sensible

Make a variable only when users need to choose a genuinely different value. Derive predictable representations in the template; keep stable files verbatim. That is how a reusable template stays small instead of becoming a second programming language.

Retrieval practice

Answer from memory before clicking. One attempt each.

1. Why does the built-in lib sanitize project_name in the package clause?

A Go package clause uses an identifier; the raw slug with hyphens is preserved where that format allows it, such as the module path.

2. What does sanitize("go-csvstream") produce?

Hyphens become underscores and letters are lowercased: go_csvstream.

3. Where is Pavona's sanitize function available?

The file renderer registers sanitize; the separate path renderer does not.

4. What happens if a path uses {{.project_name | sanitize}}?

The path renderer doesn't register sanitize; the path fails to parse with an undefined-function error.
