Lesson 03 · Pavona from the ground up

Your Template, Available by Name

Put a template where Pavona can find it, version it, and evolve it safely.

Today's win

You'll install your greeting template into an isolated XDG template home, invoke it by name from outside its directory, then change the template and prove that new projects get the change while an already-generated project stays untouched.

Two places, two jobs

A template is the source recipe. A generated project is its own output. Pavona doesn't keep them linked: changing the recipe affects the next scaffold, not projects you already made.

PlaceWhat belongs there
$XDG_DATA_HOME/pavona/templates/<name>/Reusable custom templates; default is ~/.local/share/pavona/templates/<name>/
Any separate output directoryA generated project — an independent starting point, not a live view of its template

When you run pavona new <name>, resolution checks built-in names first, then an exact directory path, then the XDG template path. So:

  • Choose a distinctive custom name; an XDG template named tool loses to the built-in tool.
  • pavona list lists built-ins only, not your personal XDG templates. (You can still invoke one by name.)
  • XDG_DATA_HOME, if set, replaces the default data root.

Hands-on: test in an isolated template home

Use the my-first-template directory from Lessons 1–2. Open a terminal in its parent directory (the directory that contains it). These commands set a temporary XDG root, so they won't change your personal template collection:

  1. Copy the template into the XDG layout. 
    export XDG_DATA_HOME="$(mktemp -d)"
mkdir -p "$XDG_DATA_HOME/pavona/templates"
cp -a my-first-template "$XDG_DATA_HOME/pavona/templates/my-first-template"
TEMPLATE="$XDG_DATA_HOME/pavona/templates/my-first-template"
    Pavona looks for $XDG_DATA_HOME/pavona/templates/<name>/config.cue, so the final directory name is the invocation name.
  2. Scaffold by name, not by path. Use a fresh output name: 
    pavona new my-first-template xdg-demo -q
cat xdg-demo/README.md
    This proves name resolution worked: the command did not mention the template's path. -q uses defaults; the positional xdg-demo supplies project_name.
  3. Put the recipe under version control. 
    git -C "$TEMPLATE" init
git -C "$TEMPLATE" status --short
    Review the listed template files. Commit a known-good starting point when ready (git add ., then git commit); if Git asks, configure your author name/email first. Generated projects are outside this template repository.
  4. Change the recipe; generate a second project. 
    printf '\nGenerated from my personal Pavona template.\n' >> "$TEMPLATE/README.md.tmpl"
pavona new my-first-template xdg-demo-v2 -q
grep 'personal Pavona template' xdg-demo-v2/README.md
grep 'personal Pavona template' xdg-demo/README.md || echo 'old project is unchanged'
    The new project contains the added line; the first one does not. Use a fresh output directory for each run.

Pavona scaffolds; it does not sync. Hydration refuses to write into a non-empty output directory. It will not overwrite, merge, or upgrade an existing project. That is a safety feature: generated output becomes yours to change. If you want the latest template, scaffold a new project and migrate your own changes deliberately.

Make it a personal template

The isolated XDG root was for practice. For regular use, keep the template in a Git repository at:

${XDG_DATA_HOME:-$HOME/.local/share}/pavona/templates/my-first-template/

Use a distinctive directory/name, keep config.cue at its root, and invoke it from any working directory with:

pavona new my-first-template my-new-project

If you already set XDG_DATA_HOME, Pavona uses that root instead of ~/.local/share. The template source can itself be a Git repository: commit a known-good version before changing it, review diffs, and try the new version by generating a fresh project.

Retrieval practice

Answer from memory before clicking. One attempt each.

1. An XDG template is named tool. What does pavona new tool resolve?

Built-in lookup happens before exact paths and XDG templates; use a distinctive name for personal templates.

2. What does pavona list show?

The command delegates to ListBuiltin; XDG templates remain directly invokable but are not listed.

3. What if the output directory already contains files?

Hydration accepts an absent or empty output directory. Pavona is a scaffold generator, not a project sync or upgrade tool.

4. What happens to an existing project when its template changes?

A generated project is an independent copy. Re-run into a fresh output directory to see the updated template.
