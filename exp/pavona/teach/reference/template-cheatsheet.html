Pavona Template Cheat Sheet

The compressed essence of template authoring. Print-friendly.

Commands

pavona list                        # show built-in templates (alias: ls)
pavona new tool my-cli             # scaffold from a built-in template
pavona new ./my-template my-proj   # scaffold from a local template dir
pavona new tool my-cli -q          # non-interactive: every variable = its default
pavona new tool my-cli -o outdir   # output dir override
pavona new tool my-cli -n my-cli   # pre-fill the project_name variable
InputEffect
new <template> [name]positional name sets the output dir and, when defined, pre-fills the project_name variable
-n / --namepre-fills project_name; the field remains visible in the interactive form
-o / --outputoutput directory (default: project_name, then output)
-q / --quietno prompts; every variable takes its declared default

Template resolution order

  1. Built-in — name matches a built-in template (tool, lib, site, tui, app, agent, pavona, monorepo-go); this check wins before all other sources
  2. Exact path — argument is a directory containing config.cue
  3. XDG data — $XDG_DATA_HOME/pavona/templates/<name>/ (default ~/.local/share); these templates are invoked by name but do not appear in pavona list
  4. Error — exit code 1

Template anatomy

my-template/
├── config.cue          # consumed by Pavona — never written to output
├── README.md.tmpl      # rendered via text/template → README.md
├── Makefile            # copied byte-for-byte
└── {{.project_name}}/  # directory names render too
    └── main.go.tmpl
FileBehavior
*.tmplrendered with the variables map as data context; suffix dropped
everything elsecopied byte-for-byte
config.cueconsumed by Pavona; never in output
dirs named {{...}}directory name is rendered as a template

config.cue patterns

package template

name:        "my-template"        // required, string
description: "A custom template"  // required, string

variables: {
	// Doc comment = the prompt shown to the user
	project_name: string                  // required, freeform text

	greeting?: string | *"Hello, World!"  // optional, freeform, default
	license?: "MIT" | "Apache-2.0"        // optional, select menu (choice)
}
CUE patternPrompt behavior
field: stringrequired freeform input (blank rejected)
field?: stringoptional freeform input
*"default"default value (pre-filled; used by -q)
"a" | "b"select menu over the literals
doc comment above fieldbecomes the prompt title

Only string-kind variables are meaningfully supported: defaults are read as strings and prompts are text/select inputs. Pavona shows all variables together in one form, sorted alphabetically. A name supplied positionally (or with -n) pre-fills project_name but does not remove the field from that form. If a choice variable's default is not one of its choices, Pavona selects the first listed choice instead.

Inside *.tmpl files

# {{.project_name}}

{{.greeting}}

{{ if .license }}License: {{.license}}{{ end }}
  • Data context is the variables map — keys are the config.cue variable names.
  • Full Go text/template syntax: {{if}}, {{range}}, pipelines, etc.
  • Pavona's sanitize helper is available only in rendered file contents: {{.project_name | sanitize}}. It lowercases, maps hyphen/underscore to underscore, and strips other characters; it is not a full validator and is unavailable in rendered paths.

Failure modes

SymptomCauseFix
template "x" not found (exit 1)no built-in, path, or XDG matchcheck spelling; ensure dir has config.cue
directory "x" exists but has no config.cuepath matched but not a templateadd config.cue at the dir root
Error parsing config.cue: …CUE validation failedname, description, variables must all exist; CUE must be valid
required values missing: …required var empty (typical in -q without -n)pass -n/--name or drop -q

Versioning a template

  • A template is just a directory: track it in git to maintain it.
  • Changing template files affects new scaffolds only — existing generated projects are snapshots and are never touched.
  • Output must be absent or empty; Pavona rejects a non-empty output directory instead of merging or overwriting it.
  • For personal cross-project use, install under ${XDG_DATA_HOME:-$HOME/.local/share}/pavona/templates/<name>/. Choose a name distinct from built-ins because those resolve first.
