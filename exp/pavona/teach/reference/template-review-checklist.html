Template Review Checklist

A compact pass before you trust a reusable Pavona template.

1. Design the seam

QuestionTemplate treatment
Does this value change between projects?Make it a config.cue variable only if the user should choose it.
Is there a safe, common answer?Declare a default; -q uses defaults.
Is it a small, closed set?Use a choice variable, and ensure the default is one of its choices.
Is the file stable for every project?Copy it verbatim (no .tmpl suffix).
Does a value need formatting?Transform it where used in a rendered file; don't create duplicate prompts for derivable forms.
Does the variant require a different file tree?Use a separate template. Pavona renders file contents and paths but does not conditionally omit files.

2. Check the template definition

  • config.cue is at the template root and defines string name, description, and variables.
  • Each variable's doc comment is a clear prompt label.
  • Every required variable has a plan for non-interactive use. A required value without a default must be supplied; --name only pre-fills project_name.
  • Optional variables render sensibly when left empty.
  • Choice defaults are members of their choice set.
  • Names rendered into paths are path-safe. The sanitize helper is only available in rendered file content, not path rendering.

3. Run a minimal smoke test

  1. Use a fresh output directory (or an existing empty one).
  2. Run a quiet scaffold with an explicit name, e.g. pavona new my-template smoke-quiet -q.
  3. Run an interactive scaffold and deliberately change one non-default answer.
  4. Check the output tree: expected names, no config.cue, no leftover .tmpl suffixes.
  5. Check rendered contents: every placeholder resolves; stable files match their sources byte-for-byte.
  6. Run the generated project's own formatter, tests, or build where applicable.
  7. After editing the template, generate into a new output directory and compare. Existing generated projects are independent snapshots.

4. Diagnose by layer

SymptomFirst check
Template not foundResolution order: built-in → exact path with config.cue → XDG. Check custom-name collisions with built-ins.
CUE/config errorSyntax, then required top-level fields: name, description, variables.
Required value missingIn -q, the variable's default is empty; supply it or define a sensible default.
Missing map key during renderCompare every {{.key}} in file contents and paths with declared variable names.
Output already existsUse a new/empty output directory. Pavona scaffolds; it does not merge or update.

Failed render recovery: a template execution error can leave a partially written throwaway output directory. Inspect it; remove or move it only if you are certain it contains just that failed test output, then retry into a fresh path.

Custom templates installed by name live at ${XDG_DATA_HOME:-$HOME/.local/share}/pavona/templates/<name>/. Keep the template source under Git and separate from generated project directories.
